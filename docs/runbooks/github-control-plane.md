# GitHub control plane — read-only webhook pilot

TrueNAS only, off by default. Set GITHUB_WEBHOOK_ENABLED=true, GITHUB_WEBHOOK_INSTALLATION_ID to the verified installation and GITHUB_WEBHOOK_SECRET via runtime Vaultwarden materialization; do not put the App PEM in the web container. POST /webhooks/github is the sole signed receiver. Use Cloudflare Tunnel with narrowly scoped Access exception and WAF exact host/path/method/IP policy, only after negative tests. GitHub signs the raw bytes with X-Hub-Signature-256; no login redirect or browser cookies. Redis is required, fixed keys, 7-day TTL, per workflow/run/attempt monotonic projection, reject stale timestamps beyond 24 h. Redis loss is NOT_OBSERVED, not an audit ledger; no delivery or approval state must depend on this projection. GET /api/homelab/github-workflows is OWNER diagnostics (same policy as health board), no raw payload or credentials. No writes to GitHub, no shell or Terraform execution. No permissions beyond actions:read in the pilot. For future dispatch, isolate a worker, exact repo/workflow/ref/SHA and operation enum, per-request short-lived token, signed challenge hash and nonce, durable audit and independent approval verification. Reuse nabla-compose Entra hardware approval workflow; its current owner-actor guard intentionally denies an App actor. Do not change it implicitly. GitHub environment and OIDC policy remain authoritative; a signed webhook is never an approval. Validate exact Access paths, HMAC negative test, Redis persistence, replay, failure and no public leakage before enabling. Runtime NOT_RUN.
