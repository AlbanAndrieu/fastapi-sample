## Avancement 21/11 — intégration fonctionnelle pilote

FastAPI : `nabla/integrations/freshrss_greader.py` implémente le reader HTTPS GReader sur URL fixée, aucun POST/writeback, filtrage public des subscriptions et contenu HTML, limite stricte des réponses. `rss_relevance_live.py` exploite le catalogue V2 vérifié, prompt Langfuse versionné avec label `production` (aucun fallback), et LiteLLM local TrueNAS port 4000 (modèle `fastapi-qwen`, clé virtuelle). CLI read-only `python -m nabla.integrations.rss_relevance_live --check` hors réseau puis `FRESHRSS_RELEVANCE_RUN_APPROVED=YES ... --once` sur TrueNAS avec compte FreshRSS séparé, secrets Vaultwarden et `FASTAPI_RUNTIME_MODE=homelab`. Cette opération ne marque pas les articles comme lus et n'envoie pas de notifications. Le chemin vers la base de données des décisions RSS et le cache Redis n'est pas encore câblé. Ne pas exécuter la version live sans prompt Langfuse réellement publié et compte service isolé.

API approbations : `GET /api/homelab/approvals/pending` lecture seule sur PostgreSQL en OWNER homelab, désactivée par défaut (`OPERATION_APPROVAL_READ_MODEL_ENABLED=false`). Rejette les requêtes avec paramètres, renvoie uniquement métadonnées et SHA, ignore les expirées. L'activation suppose migration DB et tests d'autorisation, jamais `apply` via cette API. Aucune mutation ou notification n'est câblée.
